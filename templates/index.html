Find a control

Recover the CAN ID / byte / bit behind a button, lock or switch. Tell it how many times you triggered the action; it ranks the fields that changed that many times and rejects machine-cadence chatter (rolling counters, periodic status words).

Which encoding? pulse vs toggle vs value — it changes what you recover

The same action is encoded differently depending on the control. Pick the wrong mode and the real field gets buried under look-alikes.

  • pulse bit — a button that springs back: the bit goes 0→1→0 for the moment you hold it. Momentary push-buttons (lock/unlock button, rear-defrost, steering-wheel keys). Counted as rising edges.
  • toggle bit — a state that stays: one bit flips and holds between two states. Things that latch: lock state, gear in P, a switch left on. Counted as state changes.
  • value byte — many buttons on one message: a shared byte sits at an idle value and takes a distinct code per button (steering-wheel / console clusters). Counted as bursts; each code is listed.
  • auto — tries all three and ranks them together. Start here, then narrow to one mode if the right field is buried.

Your hunt: rear-defrost “on/off/on/off” is two signals — the button press is a pulse (4 rising edges), while the defrost state it sets is a toggle. Pulse finds the button; toggle finds the status bit.

Human-cadence filter

Find a continuous signal GATE

The immobilizer's standstill gate is vehicle speed — a smooth multi-byte number, not a button, so the button finder can't see it. Drive a known maneuver during the capture (roll 0 → up → 0), load it here, and this ranks the fields that move smoothly over a real range and trace that up-and-down path. Rolling counters and checksums are rejected.

For an exact scale/offset fit, run the CLI with a reference value trace: python find_continuous.py --trace yourlog --reference gps_speed.txt

Find the gear selector GATE

The other standstill gate is gear in P/N. Gear is a small held bit-field (a nibble) — not a button and not a whole byte — so it needs its own search. Shift through the gears during the capture (P → R → N → D → …), tell it how many positions you used, and it finds the latched sub-field that holds that many stable levels.

The held codes are the gear values — identify which one is Park, then add the field to a profile as the gear gate.

Rolling counter & checksum

Find the rolling counter and crack the checksum so transmitted frames would be ECU-accepted. Leave the ID blank to scan every ID in the log.

Vehicle profile

Define a platform profile and validate it against the loaded log. Gate signals (speed, gear) must validate before a data inhibit is ever allowed — a failing gate is disqualifying.

Replay & immobilizer SIMULATION

Decode the loaded log into a vehicle-state timeline, and optionally run the immobilizer state machine over it. This is a pure replay — no CAN interface is opened and nothing is transmitted. The decode profile uses maps_to signals (distinct from the validate profile).
